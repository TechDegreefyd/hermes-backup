The Regular LMS reporting system differs from the Online track by pulling from three distinct PostgreSQL databases and merging them into a single analytical view.

## Core Databases
Data is extracted from:
1. `degreefyd_regular_lms`

Credentials for all three must be maintained in `/workspace/.env`.

## Key Logic & Transformations

### 1. Multi-Database Federation
- Data must be fetched independently from each database using the specific SQL queries provided for Admissions and Forms.
- Use `pd.concat` to merge the dataframes before processing.

### 2. Amity University Mapping
- **Requirement**: All individual Amity campus entries (e.g., Amity University Jaipur, Mumbai, Lucknow) must be mapped to a single entity: **"Amity University (All Campuses)"**.
- Implementation: `df['college_name'] = df['college_name'].apply(lambda x: "Amity University (All Campuses)" if 'Amity' in str(x) else x)`.

### 3. Config & Targets
- Uses `/workspace/regular_report_config.json`.
- If the file is missing, initialize it by extracting supervisor and counsellor names directly from the database results to ensure the framework exists for the user to add targets later.

### 4. Lead Intelligence Mapping & Milestone Logic
When reconciling data with the 'Lead Intelligence Dashboard' or similar supervisor-level tables:
- **Milestone Date Logic (User Preferred)**: Always calculate performance using actual event dates rather than current status. 
  - **ICC**: Use the `first_icc_date` (or `first_Icc_Date` for Online LMS) column. This is the "True Logic" because students who move to later stages (Application/Admission) or become "Not Interested" will lose their "ICC" status but still keep their ICC milestone date.
  - **Forms/Admissions**: Query the `course_status_journeys` table for the specific status update date within the target period.
- **Monthly Lead Performance**: To generate a report for a specific month (e.g., April) that matches user dashboards:
  1. Filter for Leads **Created** in that month.
  2. For those specific leads, count how many have an ICC date, how many have a Form Submitted status, and how many have an Admission status.
- **Supervisors**: Group data using the `assigned_to` hierarchy in the `counsellors` table. Top-level supervisors like `Gurvinder Singh` or `Manoj Kain` often have intermediate nodes like `Gurvinder To L2` or `Manoj To L3`.
- **Leads**: Count total records in the `students` table.
- **Admissions**: Count distinct `student_id` with status `Admission` and `fee_type NOT ILIKE '%partial%'`.

### 5. Connection Details
- All 4 databases (Online, Regular, CGC, Amity) are hosted on: `storage.bhugoal.cloud:54321`.
- Use `asyncpg` for high-performance async queries across these databases.

# WhatsApp File Sending via Bridge API

The Hermes `send_message` tool only sends text. For files (PDFs, images, documents), use the WhatsApp bridge's HTTP API directly.

## Key Discovery

The WhatsApp bridge (Node.js) exposes HTTP endpoints on a local port. The `send_message` tool in the gateway/platforms/whatsapp.py only calls `/send` (text). File sending requires `/send-media`.

## Finding the Bridge Port

```bash
# Find the running bridge process and its port
ps aux | grep "whatsapp-bridge" | grep -v grep
# Typical output: node ... bridge.js --port 3000 --session ...
```

## Finding Your WhatsApp Chat ID

Check the bridge log — allowed users are listed there:

```bash
tail ~/.hermes/whatsapp/bridge.log
# Look for lines like: 🔒 Allowed users: 7982487213
# Or allowlist_mismatch entries showing your chat ID format
```

The format is: `91XXXXXXXXX@s.whatsapp.net` (phone number with country code)

## Sending a File (PDF, Image, Document)

The bridge must be running (`hermes gateway start` or `hermes gateway install`).

```bash
# Find port
BRIDGE_PORT=$(ps aux | grep "whatsapp-bridge" | grep -oP -- '--port \K\d+' | head -1)
echo "Port: $BRIDGE_PORT"

# Send a PDF/document
curl -s -X POST "http://127.0.0.1:${BRIDGE_PORT}/send-media" \
  -H "Content-Type: application/json" \
  -d '{
    "chatId": "YOUR_WHATSAPP_NUMBER@s.whatsapp.net",
    "filePath": "/path/to/file.pdf",
    "mediaType": "document",
    "caption": "Optional caption text",
    "fileName": "DisplayName.pdf"
  }'

# Send an image
curl -s -X POST "http://127.0.0.1:${BRIDGE_PORT}/send-media" \
  -H "Content-Type: application/json" \
  -d '{
    "chatId": "YOUR_WHATSAPP_NUMBER@s.whatsapp.net",
    "filePath": "/path/to/image.jpg",
    "mediaType": "image",
    "caption": "Look at this!"
  }'
```

## mediaType Options

| mediaType | WhatsApp sends as | Notes |
|-----------|-------------------|-------|
| `document` | Document attachment | Use for PDF, DOCX, XLSX |
| `image` | Image | JPEG, PNG, GIF |
| `video` | Video | MP4 |
| `audio` | Audio/voice | OGG, MP3 |

The `fileName` field sets the display name for documents. The `caption` adds text above the file.

## Required Fields

- `chatId` — WhatsApp ID (format: `91XXXXXXXXX@s.whatsapp.net`)
- `filePath` — Absolute path to file, must exist and be readable

## Optional Fields

- `mediaType` — auto-inferred from extension if omitted
- `caption` — text shown above the file in WhatsApp
- `fileName` — display name for the file (defaults to filename)

## Important Notes

1. **The bridge must be running** — if `hermes gateway` isn't running, the port won't be open
2. **File must exist** — the API returns 404 if the file doesn't exist
3. **Portrait images** — WhatsApp may refuse portrait-orientation images from some phones; try re-encoding
4. **PDFs from Python** — if generating PDFs in a venv (not the hermes venv), save to `/tmp/` and send from there
5. **send_message vs /send-media** — the gateway's `send()` method calls `/send` (text only). For files, bypass the gateway and call the bridge API directly

## WHAPI Cloud Connector (Primary for Hostinger/VPS)

The WHAPI cloud connector is the preferred method for remote environments (VPS/Hostinger). It does not require a local Node.js bridge.

### Python Sending Pattern (WHAPI)

Requires `requests` and `python-dotenv`. Use `uv pip install requests python-dotenv` if `pip` is missing.

```python
import os
import base64
import requests
from dotenv import load_dotenv

# Use absolute path to the .env file
ENV_PATH = "/home/mohit/workspace/.env"
load_dotenv(ENV_PATH)

WHAPI_TOKEN = os.getenv("WHAPI_TOKEN")
WHATSAPP_GROUP = os.getenv("WHATSAPP_GROUP") # e.g. 120363426619711887@g.us

def send_pdf(file_path, caption="📊 Report"):
    if not os.path.exists(file_path):
        return False, "File not found"
        
    with open(file_path, "rb") as f:
        b64_content = base64.b64encode(f.read()).decode('utf-8')
    
    # Common Mime Types:
    # PDF: application/pdf
    # HTML: text/html
    # Excel: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
    # Image: image/jpeg
    mime_type = "application/pdf"
    file_name = os.path.basename(file_path)
    
    media_payload = f"data:{mime_type};name={file_name};base64,{b64_content}"

    headers = {
        "accept": "application/json",
        "authorization": f"Bearer {WHAPI_TOKEN}",
        "content-type": "application/json"
    }

    payload = {
        "to": WHATSAPP_GROUP,
        "media": media_payload,
        "caption": caption
    }

    # WHAPI gateway occasionally fails with DNS/NameResolutionError in WSL/Docker.
    # Always use a retry loop for robustness.
    import time
    for attempt in range(3):
        try:
            resp = requests.post("https://gate.whapi.cloud/messages/document", headers=headers, json=payload, timeout=15)
            return resp.status_code == 200, resp.text
        except Exception as e:
            if attempt == 2:
                return False, str(e)
            time.sleep(2)

if __name__ == "__main__":
    success, result = send_pdf("/home/mohit/Facebook_Ads_In_Depth_Report_V2.pdf")
    print(f"Success: {success}, Result: {result}")
```

## WHAPI Pitfalls & Troubleshooting

- **QR Code Timeout:** If `whapi_qr.png` fails to load or `vision_analyze` returns an error, check the file content with `cat whapi_qr.png`. It may contain a JSON error like `{"status":"TIMEOUT"}` instead of an actual image. This happens when the WHAPI server takes too long to generate the code.
- **Base64 Overhead:** Large images or PDFs can fail in `requests` if the base64 string is too large. For bulk sending, use a local bridge or check WHAPI's file size limits.
- **Invalid Mime-Types:** WHAPI is strict about mime-types in the `media` payload. Ensure the type matches the file extension precisely (e.g. `application/pdf` for `.pdf`).
